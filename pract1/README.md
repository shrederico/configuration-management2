# Практическая работа №1. Эмулятор командной оболочки

**Дисциплина:** Конфигурационное управление  
**Вариант:** 10  
**Язык:** Python 3 (проверено на Python 3.14)

Реализованы пять этапов варианта №10 (стр. 35–37 методички):
консольный диалог, конфигурация, ZIP-VFS, основные и дополнительные команды.
Все файловые команды работают с виртуальной файловой системой в памяти.
Реальные файлы компьютера и исходный ZIP командами эмулятора не изменяются.

## Быстрый запуск

Открыть папку `pract1` в PyCharm. В её терминале выполнить:

```sh
python3 scripts/create_vfs.py
sh run.sh --vfs examples/deep.zip
```

Первая команда создаёт три учебных ZIP. Вторая запускает эмулятор
с вложенной файловой системой. Дополнительные библиотеки не нужны:
используется только стандартная библиотека Python. Сборка не требуется.

Пример ручной демонстрации:

```text
ls
cd docs
tac notes.txt
uname
touch new.txt
ls
rm new.txt
ls
cd ..
exit
```

`tac notes.txt` выведет `three`, `two`, `one` на отдельных строках.
`uname` на macOS выводит `Darwin`. Приглашение содержит реальные имя
пользователя и имя компьютера, а также текущий каталог VFS.

## Запуск кнопкой в PyCharm

1. Один раз запустить `scripts/create_vfs.py` кнопкой Run.
2. Открыть `src/main.py` и запустить Run.
3. Без параметров откроется пустая VFS: можно выполнить `touch a`, `ls`,
   `rm a`, `uname`, `exit`.
4. Для учебной VFS открыть Run → Edit Configurations и выбрать запуск
   `main.py`. Установить Working directory в папку `pract1`, а в поле
   Parameters указать `--vfs examples/deep.zip`.
5. Для автоматического сценария добавить к Parameters
   `--script examples/stage5.txt`.

## Параметры запуска

```sh
sh run.sh --vfs examples/deep.zip --script examples/stage4.txt
```

| Параметр | Значение |
|---|---|
| `--vfs PATH` | Путь к физическому ZIP-архиву; без него пустая VFS |
| `--script PATH` | Путь к файлу команд UTF-8; без него ручной ввод |
| `-h`, `--help` | Встроенная справка по запуску |

При запуске выводятся оба пути. При прямом запуске Python относительные
пути считаются от текущего рабочего каталога. `run.sh` сначала переходит
в папку проекта, поэтому его относительные пути считаются от `pract1`.
Пути с пробелами в параметрах запуска нужно заключать в кавычки.

Стартовый скрипт выполняется построчно. На экране показывается приглашение
с командой и затем её результат. Ошибочная команда выводит сообщение,
но следующая строка выполняется. Пустые строки пропускаются. Правильный
`exit` завершает весь сеанс. Если его нет, после скрипта начинается ручной
ввод. Ошибка чтения ZIP или скрипта завершает запуск с кодом 1;
неверные параметры запуска — с кодом 2. Нормальное завершение — код 0.
Ошибки отдельных команд не завершают сеанс.

## Поддерживаемые команды

| Команда | Поведение |
|---|---|
| `ls [путь]` | Дети каталога либо имя файла; без пути текущий каталог |
| `cd [путь]` | Перейти в каталог; без пути — корень `/` |
| `tac файл [файл ...]` | Строки каждого UTF-8 файла в обратном порядке |
| `uname` | Название ядра реальной ОС |
| `touch путь [путь ...]` | Создать пустой файл или обновить время записи |
| `rm файл [файл ...]` | Удалить файлы из памяти |
| `exit` | Завершить программу |

Абсолютные пути начинаются с `/`, относительные считаются от текущего
каталога VFS. Поддерживаются `.` и `..`, выход выше корня остаётся в `/`.
`ls` не показывает скрытые имена при перечислении каталога; явно указанный
скрытый файл доступен. `touch` не стирает существующее содержимое,
обновляет время в словаре `modified` и не создаёт отсутствующие родители.
Существующий каталог также можно передать `touch` для обновления времени.
`rm` не удаляет каталоги. Ошибка одного пути в `tac`, `touch`, `rm`
не мешает обработке следующих путей.

Объём реализации: перечисленные базовые режимы, без флагов команд.
Например, `ls -l`, `rm -r` и `uname -a` дают сообщение об ошибке.
`tac` требует путь и не читает стандартный ввод. Парсер по заданию
использует `split()`: кавычки внутри команд, имена с пробелами,
перенаправления, конвейеры и раскрытие переменных не поддерживаются.
Это эмулятор указанных команд, а не полноценная системная оболочка.

## Виртуальная файловая система

ZIP читается через `zipfile` без распаковки. Пути каталогов находятся
в множестве `directories`, содержимое файлов — в словаре `files`,
в формате base64. Таким образом, сохраняются и текстовые, и двоичные
данные. Для текстового вывода `tac` декодирует UTF-8; двоичный файл
с недопустимым UTF-8 вызывает понятную ошибку.

Пути ZIP с `..`, абсолютные пути, обратные разделители и конфликты
файлов/каталогов отклоняются. Отсутствующие в ZIP записи родительских
каталогов восстанавливаются в памяти. Удаление и создание файлов не
записываются обратно: новый запуск снова читает исходный архив.

Генератор `scripts/create_vfs.py` создаёт:

- `examples/minimal.zip` — один файл;
- `examples/files.zip` — несколько файлов, пустой файл и каталог,
  двоичные данные;
- `examples/deep.zip` — текстовые и двоичные файлы, скрытый файл,
  пустой каталог и путь `docs/level2/level3/data.txt`.

Архивы запрещены в Git правилом Г1 методички. Поэтому в репозитории
хранится генератор, а ZIP создаются локально. По пожеланию пользователя
правила `*.zip` в `.gitignore` нет: перед коммитом добавлять только
исходники, тесты, текстовые примеры и документацию, не использовать
без проверки `git add .`.

## Тесты и демонстрация

Из папки `pract1`:

```sh
python3 -m unittest discover -s tests -v
```

В PyCharm: открыть файл теста и нажать Run рядом с классом тестов.
Проверяются разбор команды, параметры, выполнение скриптов, пути VFS,
двоичные данные, все команды, ошибки, переход к ручному вводу,
сохранность исходного ZIP и реальных файлов компьютера.
Тесты создают собственные данные во временной папке и удаляют их после
проверки. Генерировать учебные ZIP перед тестами не требуется.

Полная проверка, включая скрипты ОС:

```sh
sh scripts/check_all.sh
```

Автоматическая демонстрация для защиты:

```sh
sh demo.sh
```

В демонстрации намеренно встречаются ошибки: отсутствующие пути,
неподдерживаемые параметры и неизвестная команда. Это показывает,
что сеанс продолжается. Тестовые проверки должны завершиться `OK`.

| Скрипт ОС | Назначение |
|---|---|
| `check_config.sh` | Без параметров, каждый отдельно, оба вместе |
| `check_config_errors.sh` | Ошибки параметров и отсутствующий скрипт |
| `check_vfs_minimal.sh` | Минимальная VFS |
| `check_vfs_files.sh` | VFS с несколькими файлами |
| `check_vfs_deep.sh` | Не менее трёх уровней каталогов |
| `check_commands.sh` | Сценарий основных команд |
| `check_changes.sh` | Сценарий изменения VFS |
| `check_all.sh` | Тесты и все перечисленные сценарии |

Все эти скрипты находятся в `scripts/` и запускаются через `sh`.
Файлы `examples/stage2.txt` … `stage5.txt` содержат команды эмулятора,
а не команды реальной оболочки ОС.

## Функции и взаимодействие модулей

`main.py` принимает строку → `parse_command` выделяет команду →
`Shell.execute` выбирает обработчик из `COMMANDS` → обработчик обращается
к `VirtualFileSystem` → результат выводится в консоль.

| Функция / метод | Назначение |
|---|---|
| `parse_command` | Разделить ввод на имя и список аргументов |
| `parse_options` | Прочитать параметры запуска через argparse |
| `Shell.__init__` | Создать сеанс, загрузить VFS и данные ОС |
| `Shell.prompt` | Построить приглашение с текущим каталогом |
| `Shell.execute` | Обработать пустой ввод, exit, команду или ошибку |
| `run_script` | Последовательно показать и выполнить строки файла |
| `interactive` | Принимать ввод до exit, EOF или Ctrl+C |
| `main` | Настроить программу, выполнить скрипт, запустить диалог |
| `require_single` | Проверить максимум один путь и отсутствие флагов |
| `reject_options` | Отклонить неподдерживаемые флаги |
| `ls`, `cd`, `tac`, `uname` | Основные команды из таблицы выше |
| `touch`, `rm` | Изменения VFS из таблицы выше |
| `change_files` | Применить изменение к каждому указанному пути |
| `VirtualFileSystem.__init__` | Создать хранилище с корнем `/` |
| `normalize` | Привести путь к абсолютному виртуальному пути |
| `add_parents` | Восстановить неявные каталоги из архивного пути |
| `load`, `load_entry` | Прочитать ZIP и проверить его записи |
| `list_directory` | Получить отсортированные имена детей каталога |
| `read_file` | Вернуть байты из base64 |
| `VirtualFileSystem.touch` | Создать запись или обновить её время |
| `VirtualFileSystem.remove` | Удалить запись файла из памяти |
| `create_archives` | Создать три учебных ZIP на физическом диске |

Функции тестов и вспомогательные методы документированы docstring
непосредственно в `tests/`. Каждый тест имеет отдельное описание проверки.
